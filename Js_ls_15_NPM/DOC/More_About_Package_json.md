### Что такое `package.json`

Файл `package.json` — это JSON-файл в корне проекта JavaScript/Node.js, который служит основным конфигурационным файлом. 

Он описывает проект, его зависимости, скрипты и метаданные, необходимые для работы с NPM (или Yarn, PNPM, Bun). 

Это ключевой элемент для управления проектом, его зависимостями и автоматизации задач.

### Для чего нужен `package.json`:

1. **Описывает проект**:
   - Хранит метаданные: название, версия, автор, лицензия, описание и т.д.
   - Указывает точку входа (`main`, `module`) и тип модуля (`type`).
2. **Управляет зависимостями**:
   - Списки `dependencies` (производственные зависимости) и `devDependencies` (для разработки).
   - Позволяет устанавливать и обновлять библиотеки.
3. **Определяет скрипты**:
   - Команды для запуска, тестирования, сборки и других задач (например, `npm start`).
4. **Обеспечивает воспроизводимость**:
   - С `package-lock.json` фиксирует версии зависимостей для одинаковой установки на разных машинах.
5. **Публикация в npm**:
   - Необходим для публикации пакета в реестр npm (npmjs.com).
6. **Конфигурация инструментов**:
   - Указывает версии Node.js (`engines`), пути к файлам (`files`), настройки для монопозиториев (`workspaces`).

### Как создать `package.json`:

Есть два основных способа создания файла:

1. **Через команду `npm init`**:
   - Выполните в терминале в корне проекта:

     ```
     npm init
     ```
   - Ответьте на вопросы:
     - `name`: Название проекта (по умолчанию — имя папки, в нижнем регистре).
     - `version`: Версия (обычно `1.0.0`).
     - `description`: Описание проекта.
     - `entry point`: Точка входа (обычно `index.js`).
     - `test command`: Команда для тестов (например, `jest`).
     - `git repository`: URL репозитория.
     - `keywords`: Ключевые слова.
     - `author`: Имя и email автора.
     - `license`: Лицензия (по умолчанию `ISC`, часто используют `MIT`).
   - После ответов создастся `package.json` с указанными данными.
   - Для создания с настройками по умолчанию (без вопросов):
     ```
     npm init -y
     ```

2. **Вручную**:
   - Создайте файл `package.json` в корне проекта.
   - Добавьте минимальную структуру, например:

     ```json
     {
       "name": "my-project",
       "version": "1.0.0",
       "description": "My project description",
       "main": "index.js",
       "scripts": {
         "start": "node index.js"
       },
       "author": "Your Name",
       "license": "MIT"
     }
     ```
   - Затем добавляйте зависимости и скрипты по мере необходимости.

### Основные команды для работы с `package.json`:

Эти команды взаимодействуют с `package.json` через NPM:

1. **Создание и инициализация**:
   - `npm init`: Создаёт `package.json` с вопросами.
   - `npm init -y`: Создаёт `package.json` с настройками по умолчанию.

2. **Управление зависимостями**:
   - **Установка зависимости**:

     ```
     npm install <package> [или npm i <package>]
     ```
     - Добавляет пакет в `dependencies` и устанавливает его в `node_modules`.
     - Пример: `npm install express` добавит `"express": "^4.18.2"` в `dependencies`.
   - **Установка dev-зависимости**:
    
     ```
     npm install --save-dev <package> [или npm i -D <package>]
     ```
     - Добавляет в `devDependencies` (например, `npm i -D jest`).
   - **Глобальная установка**:
    
     ```
     npm install -g <package>
     ```
     - Устанавливает пакет глобально (например, `npm i -g typescript`).
   - **Установка всех зависимостей из `package.json`**:
    
     ```
     npm install [или npm i]
     ```
     - Устанавливает все `dependencies` и `devDependencies`, указанные в файле.
   - **Удаление зависимости**:
    
     ```
     npm uninstall <package>
     ```
     - Удаляет пакет из `package.json` и `node_modules`.
   - **Обновление зависимостей**:
    
     ```
     npm update
     ```
     - Обновляет пакеты до последних совместимых версий (согласно SemVer).
   - **Проверка устаревших зависимостей**:
    
     ```
     npm outdated
     ```
     - Показывает пакеты, которые можно обновить.
   - **Аудит уязвимостей**:
    
     ```
     npm audit
     ```
     - Проверяет зависимости на известные уязвимости.
     - `npm audit fix` — автоматически исправляет уязвимости, если возможно.

3. **Работа со скриптами**:
   - **Запуск скрипта**:
    
     ```
     npm run <script>
     ```
     - Выполняет команду из раздела `scripts`. Например, `npm run start` запустит `node index.js` (если так указано).
   - **Сокращённые команды**:
     - `npm start` — эквивалент `npm run start`.
     - `npm test` — эквивалент `npm run test`.
   - **Просмотр всех скриптов**:
    
     ```
     npm run
     ```
     - Показывает список доступных скриптов из `scripts`.

4. **Публикация пакета**:
   - **Публикация в npm**:
    
     ```
     npm publish
     ```
     - Публикует пакет в реестр npm (требуется авторизация через `npm login`).
     - Для scoped-пакетов (например, `@myorg/package`):
    
       ```
       npm publish --access public
       ```
   - **Проверка текущего пользователя**:
    
     ```
     npm whoami
     ```
     - Показывает, под каким аккаунтом вы авторизованы.
   - **Выход из аккаунта**:
    
     ```
     npm logout
     ```

5. **Информация о проекте**:
   - **Просмотр зависимостей**:
    
     ```
     npm list
     ```
     - Показывает дерево установленных зависимостей.
     - Для конкретной глубины: `npm list --depth=0`.
   - **Просмотр конфигурации**:
    
     ```
     npm config ls
     ```
     - Показывает настройки npm, включая данные из `.npmrc`.

### Пример `package.json`:

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "A simple Node.js app",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest",
    "lint": "eslint ."
  },
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "jest": "^29.7.0",
    "eslint": "^8.57.0",
    "nodemon": "^3.0.1"
  },
  "author": "Иван Иванов",
  "license": "MIT",
  "engines": {
    "node": ">=18.0.0"
  }
}
```

### Советы:

- **Фиксация версий**: Всегда используйте `package-lock.json` (автоматически создаётся npm) для обеспечения одинаковых версий зависимостей.
- **Игнорирование**: Добавьте `node_modules` в `.gitignore`, чтобы не загружать зависимости в репозиторий.
- **Семантическое версионирование**: Используйте формат `MAJOR.MINOR.PATCH` для `version` (например, `1.0.0`).
- **Чистота**: Регулярно проверяйте `npm outdated` и `npm audit` для поддержания актуальности и безопасности.
- **Автоматизация**: Настройте скрипты (`scripts`) для частых задач (линтинг, тестирование, деплой).

Документация: [docs.npmjs.com](https://docs.npmjs.com/cli/v10/configuring-npm/package-json).
