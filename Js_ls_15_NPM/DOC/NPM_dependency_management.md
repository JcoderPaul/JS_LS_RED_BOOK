Управление зависимостями в JavaScript/Node.js проектах осуществляется через `package.json` и пакетные менеджеры 
(NPM, Yarn, PNPM, Bun). 

Зависимости — это сторонние библиотеки или модули, которые проект использует для выполнения своих функций 
(например, Express для серверов, Jest для тестирования). Они делятся на **производственные** (`dependencies`) 
и **разработки** (`devDependencies`). 

Рассмотрим управление зависимостями с акцентом на NPM, так как это стандартный инструмент, связанный с `package.json`.

### Основные концепции:

- **Зависимости** (`dependencies`): Библиотеки, необходимые для работы приложения в продакшене (например, фреймворки, утилиты).
- **Зависимости для разработки** (`devDependencies`): Инструменты, используемые только в процессе разработки (например, тесты, линтеры, сборщики).
- **Файлы**:
  - `package.json`: Хранит список зависимостей и их версии.
  - `package-lock.json`: Фиксирует точные версии зависимостей и их подзависимостей для воспроизводимости.
- **Семантическое версионирование (SemVer)**: Формат версий `MAJOR.MINOR.PATCH` (например, `^4.18.2` — совместимые минорные обновления, `~4.18.2` — только патчи).

### Основные команды для управления зависимостями (NPM):

1. **Установка зависимостей**
   - **Установить конкретный пакет**:
     
     ```
     npm install <package> [или npm i <package>]
     ```
     - Пример: `npm install express` добавляет `express` в `dependencies` в `package.json` и устанавливает его в `node_modules`.
     - Версия добавляется в формате `^MAJOR.MINOR.PATCH` (например, `"express": "^4.18.2"`).
   - **Установить dev-зависимость**:
     
     ```
     npm install --save-dev <package> [или npm i -D <package>]
     ```
     - Пример: `npm install --save-dev jest` добавляет `jest` в `devDependencies`.
   - **Установить конкретную версию**:
     
     ```
     npm install express@4.18.2
     ```
     - Устанавливает точную версию `4.18.2`.
   - **Глобальная установка**:
     
     ```
     npm install -g <package>
     ```
     - Устанавливает пакет глобально (например, `npm i -g typescript` для CLI-утилит).
   - **Установить все зависимости из `package.json`**:
     
     ```
     npm install [или npm i]
     ```
     - Устанавливает все пакеты из `dependencies` и `devDependencies`, используя `package-lock.json` для точных версий.

2. **Удаление зависимостей**
   - **Удалить пакет**:
     
     ```
     npm uninstall <package>
     ```
     - Удаляет пакет из `package.json` и `node_modules`.
     - Пример: `npm uninstall express`.
   - **Удалить dev-зависимость**:
     
     ```
     npm uninstall --save-dev <package>
     ```
     - Пример: `npm uninstall --save-dev jest`.

3. **Обновление зависимостей**
   - **Обновить до последних совместимых версий**:
     
     ```
     npm update
     ```
     - Обновляет пакеты в пределах версий, указанных в `package.json` (например, `^4.18.2` обновится до последней `4.x.x`).
   - **Проверить устаревшие пакеты**:
     
     ```
     npm outdated
     ```
     - Показывает пакеты, которые можно обновить, с текущей, желаемой и последней версиями.
   - **Обновить до конкретной версии**:
     
     ```
     npm install express@latest
     ```
     - Устанавливает последнюю версию пакета и обновляет `package.json`.

4. **Проверка и аудит**
   - **Проверить зависимости на уязвимости**:
     
     ```
     npm audit
     ```
     - Сканирует зависимости на известные уязвимости.
     - `npm audit fix` — автоматически исправляет уязвимости, устанавливая безопасные версии.
     - `npm audit fix --force` — более агрессивное исправление, может обновить мажорные версии (осторожно!).
   - **Просмотреть дерево зависимостей**:
     
     ```
     npm list
     ```
     - Показывает все установленные зависимости и их версии.
     - Для верхнего уровня: `npm list --depth=0`.

5. **Очистка**
   - **Удалить неиспользуемые зависимости**:
     
     ```
     npm prune
     ```
     - Удаляет пакеты из `node_modules`, не указанные в `package.json`.
   - **Очистить кэш npm**:
     
     ```
     npm cache clean --force
     ```
     - Удаляет кэшированные пакеты для устранения проблем с установкой.

### Работа с `package.json` и зависимостями:

Пример `package.json` с зависимостями:

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "dependencies": {
    "express": "^4.18.2",
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "jest": "^29.7.0",
    "eslint": "^8.57.0"
  }
}
```
- **Добавление зависимости**: После `npm install express`, в `dependencies` добавится `"express": "^4.18.2"`.
- **Удаление**: После `npm uninstall lodash`, строка `"lodash": "^4.17.21"` удалится.
- **Перемещение между типами**:
  - Из `dependencies` в `devDependencies`:

    ```
    npm install --save-dev express
    ```
  - Обратно: `npm install --save-prod express`.

### Дополнительные возможности:

1. **Scoped-пакеты**:
   - Для пакетов вроде `@myorg/package`:

     ```
     npm install @myorg/package
     ```
   - Может потребоваться авторизация для приватных пакетов (`npm login`).

2. **Локальные зависимости**:
   - Установка пакета из локальной папки:

     ```
     npm install ./path/to/local-package
     ```
   - В `package.json` добавится: `"local-package": "file:./path/to/local-package"`.

3. **Семантическое версионирование**:
   - `^4.18.2`: Обновления до `4.x.x` (минорные и патчи).
   - `~4.18.2`: Только патчи (`4.18.x`).
   - `4.18.2`: Точная версия.
   - `*` или `latest`: Всегда последняя версия (не рекомендуется для продакшена).

4. **package-lock.json**:
   - Создаётся автоматически при установке/обновлении зависимостей.
   - Фиксирует точные версии всех пакетов и их подзависимостей.
   - Должен быть в репозитории для воспроизводимости.

5. **Переустановка зависимостей**:
   - Если проблемы с `node_modules`:

     ```
     rm -rf node_modules package-lock.json && npm install
     ```
   - Удаляет старые зависимости и устанавливает заново.

### Советы:

- **Фиксация версий**: Всегда коммитьте `package-lock.json` в репозиторий для стабильности.
- **Оптимизация**: Используйте `npm ci` вместо `npm install` в CI/CD для быстрой и точной установки (требует `package-lock.json`).
- **Чистота**: Регулярно проверяйте `npm outdated` и `npm audit` для актуальности и безопасности.
- **Монопозитории**: Для нескольких проектов используйте `workspaces` в `package.json`:

  ```json
  "workspaces": ["packages/*"]
  ```
- **Изоляция**: Не делайте зависимости глобальными, если они нужны только в проекте.
- **Кэш**: Если установка зависает, попробуйте `npm cache clean --force`.

### Пример сценария:

1. Создайте проект:

   ```
   npm init -y
   ```
2. Установите зависимости:

   ```
   npm install express
   npm install --save-dev jest
   ```
3. Проверьте зависимости:

   ```
   npm list --depth=0
   ```
4. Обновите устаревшие:

   ```
   npm outdated
   npm update
   ```
5. Проверьте на уязвимости:

   ```
   npm audit
   npm audit fix
   ```
